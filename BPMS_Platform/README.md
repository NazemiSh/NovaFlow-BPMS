## ۱. معرفی کلان سامانه نوافلو

**نوافلو (NovaFlow)** یک بستر یکپارچه، بومی و جامع سازمانی در کلاس سازمانی (Enterprise Edition) برای دیجیتالی‌سازی، مکانیزاسیون فرآیندها، طراحی بدون کدنویسی (No-Code/Low-Code) فرم‌های اطلاعاتی، اعمال قوانین پیشرفته کسب‌وکار (BRMS)، مدیریت گردش‌کارهای تاییداتی و پایش هوشمند شاخص‌های سازمانی است.

این سامانه به منظور رفع کامل گلوگاه‌های مکاتبات کاغذی، حذف تاخیرهای اداری، افزایش شفافیت تصمیم‌گیری و ارائه اسناد رسمی استاندارد طراحی شده است. سامانه نوافلو به طور کامل در شبکه‌های ایزوله سازمانی (Air-Gapped / Intranet) بدون هیچ‌گونه وابستگی به اینترنت خارجی مستقر می‌گردد و از کلیه الزامات امنیتی، محرمانگی داده‌ها و استانداردهای فناوری اطلاعات سازمان‌ها پشتیبانی می‌کند.

## ۲. معماری فنی و فناوری‌های هسته

سامانه نوافلو بر مبنای **معماری سه‌لایه مدرن و تفکیک‌شده (3-Tier Decoupled Architecture)** به صورت کاملاً **API-First** پیاده‌سازی شده است:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        لایه رابط کاربری (Frontend SPA)                 │
│  React 18 • Vite • Tailwind CSS • Jalaali.js • Lucide • 3D Modern Icons│
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ RESTful JSON APIs + JWT Auth
┌───────────────────────────────────▼────────────────────────────────────┐
│                  هسته منطق و سرویس‌ها (Backend Web API)                 │
│        ASP.NET Core (.NET 8) • C# 12 • EF Core • Dynamic Schema        │
│    BRMS Engine • Workflow Engine • SMTP Service • LDAP Auth Client     │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ ADO.NET / EF Core Connection
┌───────────────────────────────────▼────────────────────────────────────┐
│                     پایگاه داده (Persistence Layer)                    │
│     Microsoft SQL Server (2016-2025) / PostgreSQL • Collation فارسی    │
│            جداول رابطه‌ای ساختاریافته + JSON Schemas ذخیره‌شده         │
└────────────────────────────────────────────────────────────────────────┘
```

### مشخصات فنی فناوری‌ها:
* **بک‌اند (Core Services):** فریم‌ورک `ASP.NET Core (.NET 8.0)` در حالت بهینه InProcess IIS، کدنویسی با C# 12، مدیریت دسترسی با JWT Bearer Token و هش ایمن رمزهای عبور با `PBKDF2`.
* **فرانت‌اند (Single Page Application & PWA):** پلتفرم `React 18` مجهز به باندلر فوق‌سریع `Vite`، استایل‌دهی با `Tailwind CSS`، ساختار کاملاً راست‌چین (`RTL`)، واکنش‌گرا (`Responsive`) در موبایل و دسکتاپ، همراه با مانیفست استاندارد **PWA**، سرویس‌ورکر **Network-First** (`sw.js`) و موتور آفلاین اسکنر بارکد/QR.
* **پایگاه‌داده (Database Layer):** پشتیبانی رسمی از `Microsoft SQL Server` با کالکشن استاندارد فارسی (`Persian_100_CI_AI`) با امکان استفاده از `PostgreSQL`. ذخیره‌سازی داده‌های ساختاری و اسکیمای فرم‌ها در مدل ترکیبی Relational + JSON.
* **استقرار یکپارچه (Single-Port Hosting):** با استفاده از ماژول `IIS URL Rewrite 2.1`، تمام فایل‌های استاتیک کامپایل‌شده فرانت‌اند در پوشه `wwwroot` هسته بک‌اند ادغام شده و کل سامانه روی یک پورت شبکه در IIS میزبانی می‌شود.
* **امنیت انتقال (HTTPS / Wildcard SSL / HSTS / Reverse Proxy):** پشتیبانی بومی در هسته `.NET 8` و اسکریپت `Deploy-BPMS.ps1` از راه‌اندازی پورت `443` با گواهی‌های SSL استاندارد و Wildcard (`*.domain`) همراه با **SNI**، ریدایرکت خودکار و دائمی **۳۰۱** از HTTP به HTTPS، هدر امنیتی **HSTS** و میدل‌ور `UseForwardedHeaders` (`X-Forwarded-For` / `X-Forwarded-Proto`) جهت استقرار بی‌نقص پشت WAF / CDN / Reverse Proxy هنگام انتشار اینترنتی.

## ۳. قابلیت‌های کلیدی و ماژول‌های سامانه

### ۳.۱. فرم‌ساز پویا و بصری (Dynamic Form Builder)
* **طراحی بدون کدنویسی (No-Code):** کشیدن و رها کردن فیلدها، تغییر ترتیب، تعریف برچسب‌ها و راهنماهای فیلدها در محیطی الهام‌گرفته از تجربه کاربری مدرن Google Forms.
* **تنوع گسترده فیلدهای اطلاعاتی:** پشتیبانی از بیش از ۱۰ نوع فیلد شامل متن تک‌خطی و چندخطی، فیلدهای عددی با قابلیت تعیین **واحد سنجش** (ریال، تومان، کیلوگرم، درصد، عدد و...)، انتخاب تکی (Dropdown)، انتخاب چندگانه (Multi-Select Checkboxes)، چک‌باکس‌های تاییدیه، تاریخ بومی شمسی با انتخابگر تقویمی، و پیوست فایل‌های مجاز با محدودیت حجم و پسوند.
* **سکشن‌بندی چندمرحله‌ای فرم‌ها:** تقسیم‌بندی فیلدهای پیچیده به بخش‌های منطقی به منظور تسهیل ورود اطلاعات توسط کاربران.
* **اعتبارسنجی زنده (Client & Server Validation):** بررسی فیلدهای اجباری، تطابق الگوها، بازه‌های عددی مجاز و نمایش هشدارهای خوانا به زبان فارسی.
* **قوانین اعتبارسنجی فرمولی پیش از ارسال فرم (`Formula Validation Rules`):** امکان تعریف یک یا چند قانون شرطی در تنظیمات فرم با استفاده از پارسر امن بدون `eval` (`SafeMathParser`)، پشتیبانی از عملگرهای مقایسه‌ای (`==`, `!=`, `>`, `<`, `>=`, `<=`) با تلورانس اعشاری `0.01`، عملیات ریاضی و توابع جداول (`SUM(جدول.ستون)` و `COUNT(جدول)`) به همراه دکمه‌های درج سریع فیلدها و جداول و پیام خطای فارسی اختصاصی؛ در زمان پرکردن فرم، قوانین به صورت زنده ارزیابی شده و در صورت عدم برقراری شرط، باکس هشدار قرمز بالای دکمه ثبت نمایش داده شده و دکمه ارسال تا رفع خطا غیرفعال می‌ماند.

### ۳.۲. موتور قوانین کسب‌وکار (BRMS Engine)
* **تعریف شروط پویای اعتبارسنجی و محاسبات:** امکان تعریف روابط منطقی میان فیلدها (مانند محاسبه خودکار حاصل‌ضرب، مجموع، درصدها و مالیات).
* **شروط ورود به مراحل تایید:** ارزیابی فیلدهای فرم جهت تعیین مسیر گردش‌کار (به عنوان مثال: مبالغ بیش از ۵۰۰ میلیون ریال نیازمند تایید مدیرعامل).
* **شروط پرش خودکار (`Skipped`):** در صورتی که شرط ورود به یک مرحله احراز نگردد، سامانه به صورت کاملاً خودکار آن مرحله را با ثبت لاگ رسمی «عدم احراز شرط (عبور)» و درج نماد بازگشت/پرش `↶` پشت سر گذاشته و پرونده را مستقیماً به مرحله واجد شرایط بعدی هدایت می‌کند.

### ۳.۳. موتور گردش‌کار چندمرحله‌ای و ماتریس تاییدات (Workflow Engine)
* **انعطاف در انواع مراحل گردش‌کار:**
  * **حالت `ANY` (هر یک از تاییدکنندگان):** پرونده به گروهی از افراد ارجاع داده شده و اقدام اولین نفر باعث پیشبرد مرحله می‌شود.
  * **حالت `ALL` (تمام تاییدکنندگان):** نیازمند تایید هم‌زمان کلیه اعضای تعیین‌شده در آن مرحله به صورت موازی.
  * **حالت `CC` (رونوشت و اطلاع‌رسانی):** ارسال یک نسخه از پرونده جهت آگاهی اشخاص بدون توقف در روند پیشرفت گردش‌کار.
* **کارتابل جامع ورودی و پیگیری (`Inbox` / `Outbox` / `CC`):**
  * فیلتر پیشرفته بر اساس کد پیگیری، نام فرآیند، فرستنده و بازه زمانی.
  * امکان تایید، رد با ذکر دلیل اجباری، یا عودت جهت اصلاح به مرحله قبل.
* **استپر گرافیکی هوشمند (Interactive Stepper):**
  * نمایش زنده مسیر گردش‌کار از راست به چپ.
  * تفکیک بصری با نشانگرهای رنگی: سبز برای مراحل تاییدشده، زرد برای مرحله فعال جاری (`⏳ در انتظار اقدام`)، خاکستری با نماد `↶` برای مراحل عبور داده‌شده شرطی، و بج‌های ملایم خاکستری `🕒 در نوبت تایید` برای مراحل آتی.
  * پاپ‌آپ تفصیلی نمایش افراد حاضر در مرحله، تاریخ اقدام و هامش‌های ثبت‌شده.

### ۳.۴. نظرسنجی‌های عمومی سازمانی (Public Surveys)
* **اشتراک‌گذاری بدون نیاز به احراز هویت:** قابلیت تولید لینک عمومی اختصاصی برای فرم‌های نظرسنجی یا ثبت پیشنهادها جهت استفاده مراجعان خارج از سازمان یا پرسنل بدون اکانت کاربری.
* **کنترل نرخ ثبت و مقابله با هرزنامه:** مکانیزم Rate-Limiting بر پایه IP و کوکی جهت جلوگیری از ارسال تکراری.
* **داشبورد تحلیلی نتایج:** نمودارهای آماری تجمیعی، میانگین امتیازات، درصد مشارکت و خروجی اکسل نتایج نظرسنجی.

### ۳.۵. هوش تجاری (BI) و گزارش‌ساز مبتنی بر هوش مصنوعی (AI Query Builder)
* **پرس‌وجو به زبان طبیعی فارسی:** امکان نگارش سوالات مدیریتی به زبان مادری (مانند: *«لیست درخواست‌های خرید بیش از ۵۰ میلیون تومان در فصل پاییز که به تایید مالی رسیده‌اند»*).
* **تولید کوئری‌های امن T-SQL (فقط خواندنی):** تبدیل هوشمندانه پرامپت فارسی به دستورات استاندارد SQL با رعایت کامل محدودیت‌های Read-Only و جلوگیری از حملات SQL Injection.
* **یکپارچگی با Microsoft Power BI:** تولید خودکار اسکریپت ساخت `SQL View` برای پایگاه‌داده به گونه‌ای که جداول بدون اسکیما (EAV/JSON) به نماهای رابطه‌ای تمیز تبدیل شده و به سادگی به عنوان منبع داده در Power BI قرار می‌گیرند.

### ۳.۶. موتور چاپ و صدور اسناد رسمی PDF با بارکد QR
* **طراح قالب چاپ اختصاصی (Print Template Designer):** ویرایشگر بصری جهت تنظیم اندازه سربرگ، حاشیه‌ها، انتخاب فونت، نمایش/مخفی‌سازی فیلدهای مشخص و جانمایی عناصر چاپی با نوار ابزار فشرده تک‌ردیفه.
* **باکس‌های خلاصه و محاسبات فرمولی (Calculated Boxes):** امکان تعریف و درج کادرهای محاسباتی پویا (نظیر جمع کل مبالغ، محاسبه مالیات بر ارزش افزوده، درصد تخفیف، میانگین و شاخص‌های آماری) با موتور ارزیابی امن عبارات ریاضی (Safe Math Parser بدون استفاده از `eval`)، پشتیبانی از چهار عمل اصلی، پرانتزها، درصد و توابع آماری روی جداول اقلام (`SUM`, `AVG`, `COUNT`, `MIN`, `MAX`, `ROUND`)، دکمه‌های درج سریع توکن‌ها (Clickable Chips)، پیش‌نمایش زنده نتایج و تنظیمات تفکیک ارقام سه‌رقمی و اعشار.
* **جدول استاندارد تاییدات و امضاها:** تولید خودکار جدولی رسمی در انتهای برگه شامل نام ثبت‌کننده اولیه، تاریخ و ساعت ثبت، و نام و سمت تاییدکنندگان هر مرحله با درج مهر الکترونیک وضعیت تایید.
* **خوانایی وضعیت‌های در جریان:** نمایش مراحل آتی با بج روشن و استاندارد `🕒 در نوبت تایید` جهت شفافیت فرآیندهای نیمه‌کاره.
* **اصالت‌سنجی دیجیتال و بارکد QR:** درج کد رهگیری یکتای پرونده به همراه QR Code اصالت‌سنجی جهت اسکن سریع و استعلام اعتبار برگه توسط بازرسان و واحدهای مالی.
* **جدول رسمی پیوست‌های واقعی پرونده:** استخراج دقیق و نمایش اسناد آپلودشده واقعی در انتهای برگه با مخفی‌سازی خودکار جدول، بارکد و گزینه‌های تصاویر در صورت عدم وجود فایل پیوست.

### ۳.۷. رابط کاربری مدرن، تم سه‌حالته و آیکن‌های سه‌بعدی
* **پشتیبانی از ۳ حالت نمایشی:**
  * **تم تاریک (Dark Mode):** با استایل اختصاصی و آیکن‌های ایزومتریک مدرن سه‌بعدی (3D Icons) جهت کاهش خستگی چشم در کارکردهای طولانی‌مدت.
  * **تم روشن (Light Mode):** طراحی شفاف، تمیز و سازگار با استانداردهای رسمی اداری.
  * **حالت سیستم (System Mode):** انطباق خودکار با تم انتخابی سیستم‌عامل کاربر.
* **آیکنوگرافی سه‌بعدی:** مجموعه‌ای از آیکن‌های اختصاصی غنی در منوها و کارت‌های فرآیندی جهت ارتقای هویت بصری نرم‌افزار.

### ۳.۸. تقویم بومی خورشیدی (Jalali Calendar)
* محاسبات دقیق سال‌های کبیسه خورشیدی بر پایه کتابخانه `jalaali-js`.
* انتخابگر تاریخ (DatePicker) با محیط تقویمی ماهانه شمسی، امکان انتخاب سریع ماه و سال، و اعتبارسنجی بازه‌های زمانی مجاز.

### ۳.۹. یکپارچگی با اکتیو دایرکتوری و امنیت سازمانی (Active Directory / LDAP)
* **احراز هویت ترکیبی (Hybrid Auth):** قابلیت ورود هم‌زمان با حساب‌های دامین سازمانی (`sAMAccountName`) و حساب‌های محلی ایجادشده در سیستم.
* **ایجاد خودکار پروفایل:** ساخت خودکار کاربر در پایگاه‌داده به محض اولین لاگین موفق با اکتیو دایرکتوری.
* **کنترل دسترسی نقش‌محور (3-Tier RBAC):**
  * `Admin`: دسترسی کامل به تنظیمات زیرساخت، فرم‌ساز، فرآیندها، تایید نهایی و کاربران.
  * `SuperUser`: امکان طراحی فرم و تعریف گردش‌کار، بدون دسترسی به تنظیمات زیرساختی.
  * `User`: دسترسی به کارتابل شخصی، ثبت فرم و پیگیری پرونده‌ها.

### ۳.۱۰. درگاه اعلان‌های ایمیلی (SMTP Notification Gateway)
* ارسال خودکار ایمیل اطلاع‌رسانی به گیرندگان در هنگام ارجاع پرونده جدید، رد یا تایید نهایی.
* پشتیبانی از پروتکل‌های امنیتی SSL/TLS، احراز هویت سروری و قالب ایمیلی استاندارد سازمانی.

### ۳.۱۱. ماژول بانک داده‌های مرجع (Master Data Hub) و اتصال به پایگاه‌های داده خارجی
* **اتصالات رمزنگاری‌شده SQL Server (`MasterDataConnections`):**
  * مدیریت ارتباط مستقیم با پایگاه‌های داده سازمانی با رمزنگاری پیشرفته کلید متقارن AES-256 برای گذرواژه‌ها و ساخت ایمن رشته اتصال با استفاده از `SqlConnectionStringBuilder` جهت تضمین جلوگیری از خطاهای پیکربندی و حملات Injection.
  * **پشتیبانی از دو مدل احراز هویت در اتصال به دیتابیس‌های بیرونی:**
    1. **SQL Server Authentication:** اتصال از طریق نام کاربری و کلمه عبور اختصاصی دیتابیس مبدأ با ذخیره‌سازی ایمن و رمزنگاری‌شده.
    2. **Windows / Active Directory Authentication:** اتصال بر مبنای احراز هویت ویندوزی؛ شامل بهره‌گیری از هویت پیش‌فرض سرویس IIS (Application Pool Identity) و یا **استفاده از سرویس اکانت اختصاصی دامنه (`DOMAIN\svc_account`)** به همراه کلمه عبور رمزنگاری‌شده از طریق مکانیزم جعل هویت امن ویندوز (**Windows Impersonation** با توابع `LogonUser` و `WindowsIdentity.RunImpersonatedAsync`).
  * قابلیت تست زنده و برخط اتصال قبل از ذخیره‌سازی نهایی همراه با گزارش دقیق وضعیت دسترسی و نسخه دیتابیس.
* **ساخت جداول مرجع به سه روش چندمنظوره:**
  * **ورود دستی (`Manual`):** تعریف ساختار ستون‌ها و مدیریت مستقیم سطرها از طریق پنل مدیریتی برای داده‌های پایه اختصاصی فرآیندها.
  * **ایمپورت تعاملی فایل Excel / CSV (`Excel`):** بارگذاری فایل‌های `.xlsx`، `.xls` (باینری BIFF8، SpreadsheetML XML و HTML Table) و `.csv` (تشخیص خودکار جداکننده و انکودینگ UTF-8 / Windows-1256) بدون نیاز به پیش‌نیاز خارجی، مجهز به **انتخابگر شیت (`Sheet Selector`)** برای فایل‌های چندصفحه‌ای، **استخراج خودکار سرستون‌ها با چک‌باکس انتخاب ستون‌های دلخواه** (به همراه تولید خودکار کد انگلیسی و تشخیص نوع داده `string` / `number` / `date` با حفظ صفرهای ابتدایی)، **پیش‌نمایش زنده ۱۰ ردیف اول** و **اعتبارسنجی کلید یکتا (تشخیص مقادیر خالی و تکراری در تمام ردیف‌های شیت)** پیش از ثبت، ذخیره یکپارچه ساختار و ورود داده‌ها در تعریف جدول جدید، و **نگاشت و به‌روزرسانی گزینشی ستون‌ها (`Partial Column Upsert`)** با حفظ مقادیر ستون‌های تیک‌نخورده در جداول موجود (همراه با دانلود قالب نمونه UTF-8).
  * **ساخت مستقیم از روی کوئری SQL (`SqlQuery`):** اتصال زنده به دیتابیس‌های سازمانی (نظیر ERP، مالی یا انبارداری) با **اعتبارسنجی اکید فقط-خواندنی** (صرفاً دستورات `SELECT` یا `WITH` و ممانعت قطعی از اجرای کلمات کلیدی تغییردهنده نظیر `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `EXEC`, `TRUNCATE`) به همراه **تشخیص خودکار ستون‌ها و ساختار داده (`Schema Auto-Discovery`)** از طریق اجرای آزمایشی امن `TOP 10` و **پشتیبانی کامل و بومی از عبارات `ORDER BY` و Common Table Expressions (CTE)** بدون نیاز به Wrap شدن در Derived Table.
* **بازبینی کامل داده‌ها و فیلتر پیش از فراخوانی (`Full Data Preview & Pre-Sync Filtering`):**
  * امکان مشاهده کل خروجی کوئری پیش از ذخیره یا همگام‌سازی از طریق اندپوینت اختصاصی `preview-full` با صفحه‌بندی فوق‌العاده سریع و جستجوی سراسری در لحظه.
  * **تعریف قوانین فیلتر دائمی روی ستون‌ها (`FilterRulesJson`):** اعمال فیلترهای استخراجی پیش از ورود داده‌ها به کش با عملگرهای منطقی استاندارد:
    * `equals` (برابر با)
    * `not_equals` (نامساوی با)
    * `contains` (شامل عبارت)
    * `not_contains` (شامل نشود)
    * `starts_with` (شروع شود با)
    * `gt` (بزرگتر از)
    * `lt` (کوچکتر از)
    * `is_not_empty` (خالی نباشد)
  * **امکان استثنا کردن موردی رکوردها (`ExcludedKeysJson`):** انتخاب دستی رکوردهای خاص از لیست پیش‌نمایش بر پایه ستون کلید یکتا جهت جلوگیری از ورود آن‌ها به پایگاه داده و کش نوافلو.
* **زمان‌بند پیشرفته مشابه Power BI Report Server (`Advanced PBI-Style Scheduler`):**
  * موتور زمان‌بندی هوشمند در پس‌زمینه (`MasterDataSyncHostedService` و `MasterDataSchedulerEngine`) منطبق بر منطقه زمانی رسمی ایران (**`UTC +03:30 Iran Standard Time`**) و تقویم خورشیدی (`PersianCalendar`).
  * **پشتیبانی از ۶ الگوی تکرار پیشرفته:**
    1. **غیرفعال (`None`):** همگام‌سازی صرفاً به صورت دستی با کلیک روی دکمه «همگام‌سازی اکنون».
    2. **یکبار اجرا (`Once`):** اجرای تک‌باره در تاریخ و ساعت مشخص شمسی یا میلادی.
    3. **ساعتی (`Hour`):** اجرا در فواصل ساعتی و دقیقه‌ای معین (مثلاً هر ۲ ساعت یکبار).
    4. **روزانه (`Day`):** اجرا در بازه زمانی روزانه با قابلیت فعال‌سازی گزینه **«فقط روزهای کاری شنبه تا چهارشنبه» (`WorkdaysOnly`)** جهت جلوگیری از بار پردازشی بی‌مورد در تعطیلات رسمی.
    5. **هفتگی (`Week`):** اجرا در روزهای انتخابی هفته (شنبه، یکشنبه، دوشنبه، سه‌شنبه، چهارشنبه، پنج‌شنبه، جمعه).
    6. **ماهانه (`Month`):** اجرا در ماه‌های منتخب سال شمسی در روزهای مشخص ماه (مثلاً روز اول و پانزدهم) و یا در **آخرین روز ماه (`LastDayOfMonth`)** متناسب با طول ماه‌های تقویم جلالی (۳۱ روزه، ۳۰ روزه و ۲۹ روزه).
  * تعیین تاریخ شروع (`startDate`) و تاریخ پایان (`endDate`) برای محدودسازی بازه اعتبار زمان‌بندی همگام‌سازی.
* **الگوریتم هوشمند Upsert و غیرفعال‌سازی نرم (Soft-Deactivation):**
  * شناسایی و تفکیک بر پایه ستون کلید یکتا (`UniqueKeyColumn`).
  * درج اقلام جدید و به‌روزرسانی رکوردهای تغییریافته به صورت دسته‌ای (Batch Processing).
  * غیرفعال‌سازی نرم اقلام حذف‌شده از مبدأ (`IsActive = false`) جهت حفظ ۱۰۰٪ اصالت و یکپارچگی ارجاعات در فرم‌ها و پرونده‌های ثبت‌شده سال‌های گذشته بدون شکستن پیوندهای اطلاعاتی.
* **معماری کش محلی دو‌لایه با کارایی بالا (Two-Tier High-Performance Caching):**
  * **لایه اول (آینه پایگاه‌داده محلی):** ذخیره‌سازی داده‌ها در جدول `MasterDataRecords` با ایندکس مرکب جهت عملکرد بی‌وقفه و تضمین دسترس‌پذیری ۱۰۰٪ حتی در صورت قطع موقت شبکه یا از کار افتادن سرورهای مبدأ.
  * **لایه دوم (کش کلاینت مبتنی بر VersionHash):** ارائه API سبک مصرف سریع که ابتدا هش نسخه جدول را بررسی کرده و در صورت عدم تغییر، از داده‌های کش حافظه مرورگر استفاده می‌کند و زمان پاسخ‌دهی را به کمتر از چند میلی‌ثانیه می‌رساند.

### ۳.۱۲. جداول اقلام پویا و فیلدهای مرجع چندجدولی در فرم‌ساز و چاپ PDF
* **فیلد انتخاب از مرجع (`master_lookup`):** جستجوی هم‌زمان و لحظه‌ای روی کد و نام در دراپ‌داون چندستونه، انتخاب سریع آیتم‌ها و نگاشت خودکار سایر فیلدهای فرم (`Auto-Fill Mapping`) بر اساس مقادیر ستون‌های داده مرجع با امکان تعیین قفل فقط‌خواندنی برای مقادیر پرشده.
* **جدول اقلام تکرارشونده پویا (`repeater_grid` / `table`):**
  * **اتصال مستقل و هم‌زمان چندجدولی (Multi-Table Binding):** امکان تعریف و افزودن چندین جدول مجزا در یک فرم سازمانی، که هر جدول (و حتی هر ستون داخل آن) می‌تواند به یک جدول مرجع کاملاً مستقل متصل باشد (مثلاً ستون کالا به بانک کالاها، و دراپ‌داون مرکز هزینه به بانک مراکز هزینه).
  * **انتخاب آبشاری در ردیف جدول (`Cascading Lookup`):** امکان تعریف فیلتر وابسته برای ستون‌های مرجع داخل `Repeater Grid` (انتخاب ستون مبدا در همان ردیف و ستون متناظر در جدول مرجع مقصد) به‌گونه‌ای که در هر ردیف صرفاً رکوردهای متناظر با مقدار انتخاب‌شده در ستون مبدا همان ردیف نمایش داده شوند و با تغییر ستون مبدا، مقدار ستون‌های وابسته در همان ردیف به صورت خودکار ریست شود.
  * **پرکردن خودکار ستون‌های هم‌ردیف (`Row Auto-Fill`):** نگاشت خودکار ستون‌های جدول مرجع به سایر ستون‌های همان ردیف (مانند تکمیل خودکار نام کالا و وزن گرم با انتخاب کد کالا، یا درج ضریب تبدیل با انتخاب واحد سنجش) همراه با قفل فقط‌خواندنی جهت جلوگیری از خطای ورود داده.
  * **ستون‌های محاسباتی با فرمول زنده (`Calculated Columns`):** تعریف فرمول‌های ریاضی پویا میان ستون‌های هر ردیف (مانند `({Qty} * {ratio} * {Gr}) / 1000` یا `col_qty * col_price`) با پارسر امن بدون `eval` و جمع‌پذیری مستقیم نتیجه آن در توابع `SUM(جدول.ستون)` در باکس‌های محاسباتی چاپ و قوانین اعتبارسنجی فرم.
  * **سطر جمع کل جدول (`showSummaryRow`):** محاسبه و نمایش زنده مجموع ستون‌های عددی و محاسباتی در فوتر جدول فرم، کارتابل و چاپ.
  * **ذخیره‌سازی اسنپ‌شات منجمد (Frozen Data Snapshot):** ثبت نسخه ایستا از داده‌های مرجع در زمان ارسال فرم جهت تضمین عدم تغییر سوابق فرآیندی در صورت تغییرات آتی جدول مبدأ.
* **رندر و چاپ رسمی اسناد در PDF:** خروجی برگه چاپی رسمی با جدول‌بندی خوانا و تراز راست‌به‌چپ اقلام همراه با سطر جمع کل، امضاهای تاییدکنندگان و بارکد QR اصالت‌سنجی.
* **خروجی استاندارد اکسل/CSV سطر به سطر (Denormalized Export):** صدور تفکیک‌شده اقلام جدول به همراه ستون‌های هدر فرم (کد رهگیری، وضعیت، ثبت‌کننده، تاریخ و فیلدهای پایه) در قالب ردیف‌های مجزا جهت اتصال مستقیم به PivotTable و توابع محاسباتی اکسل، همراه با **حفظ ۱۰۰٪ صفر ابتدای اعداد متنی (مانند کد کالای `000023`، شماره موبایل یا کد ملی)** از طریق قالب‌بندی متنی فرمول اکسل (`="000023"`).
* **پشتیبانی کامل موتور هوش مصنوعی (AI Query Builder) از ساختار جداول اقلام:** ارسال اسکیمای ستون‌های داخلی جداول اقلام در پرامپت تولید کوئری جهت بهره‌گیری از عملگر پیشرفته `CROSS APPLY OPENJSON(s.FormDataJson, '$.gridId') WITH (...)` در T-SQL برای استخراج و گزارش‌گیری سطر به سطر اقلام به زبان طبیعی فارسی.

### ۳.۱۳. ورود سریع با کیبورد (`Keyboard-First UX`) و ثبت پیوسته (`Submit & New`)
* **مکانیزم ثبت پیوسته (Continuous Entry):**
  * دکمه اختصاصی **«ثبت و ورود مورد بعدی»** در کنار سوئیچ حالت ثبت پیوسته در فرم ثبت درخواست.
  * ارسال موفق پرونده به جریان کاری، نمایش اعلان کوتاه غیرمسدودکننده (`Toast`) همراه با کد رهگیری، ریست فوری تمامی فیلدها و ردیف‌های جدول فرم، و قرارگیری خودکار مکان‌نما روی اولین فیلد ورودی جهت ثبت بدون وقفه آیتم بعدی بدون نیاز به باز و بستن مودال یا مراجعه مجدد به منو.
* **پیمایش یکپارچه و بهینه با کلیدهای میانبر:**
  * **فوکوس اولیه هوشمند:** به محض باز شدن فرم، مکان‌نما روی اولین فیلد فعال قرار می‌گیرد.
  * **هدایت با `Enter`:** زدن اینتر در فیلدهای متنی تک‌خطی به جای ارسال زودهنگام فرم، فوکوس را به فیلد بعدی منتقل می‌کند.
  * **ثبت فوری با `Ctrl + Enter`:** ارسال مستقیم فرم (یا عملیات ثبت و ورود بعدی در حالت پیوسته).
  * **پیمایش کیبورد در لیست‌های مرجع:** جستجو با تایپ، جابجایی بین گزینه‌ها با کلیدهای جهت‌نما `ArrowUp / ArrowDown` و تایید انتخاب با `Enter` یا `Tab` همراه با پرش مستقیم فوکوس به اولین ستون قابل ویرایش بعدی (مانند تعداد).
  * **پرش هوشمند `Tab` و ایجاد خودکار سطر با `Enter`:** با فشردن کلید `Tab`، مکان‌نما تمامی ستون‌های قفل‌شده و خودکار (Auto-Fill و ستون‌های محاسباتی) را رد کرده و مستقیماً به سلول قابل ویرایش بعدی می‌رود؛ در آخرین ستون ردیف نیز با زدن `Enter` (یا `Tab` در آخرین ردیف)، یک سطر جدید افزوده شده و فوکوس مستقیماً به فیلد مرجع ردیف جدید منتقل می‌شود (همراه با باز شدن خودکار دراپ‌داون جستجو).
  * **کلید میانبر حذف ردیف جدول:** استفاده از `Alt + Delete` برای حذف سریع ردیف فعال بدون نیاز به موس.

### ۳.۱۴. مدیریت اسناد و خروجی استاندارد فایل‌های پیوست (Web File Explorer، اکسل و ضمیمه PDF)
* **کاوشگر امن اسناد و پوشه تحت وب (`Web File Explorer UI`):**
  * صفحه اختصاصی و مدرن در مسیر `/attachments/:trackingCode` با معماری واکنش‌گرا و ناوبری شفاف (`خانه / پیوست‌های پرونده {trackingCode}`).
  * نمایش متادیتای کامل فایل‌ها شامل آیکن‌های اختصاصی بر اساس نوع فایل (PDF، Word، Excel، تصاویر و بسته‌های فشرده)، حجم دقیق (KB/MB)، نوع و تاریخ بارگذاری شمسی.
  * امکان پیش‌نمایش تصویر (Lightbox) و دانلود تک‌تک اسناد با اعتبارسنجی سطح دسترسی کاربر به پرونده بدون فعال‌سازی قابلیت ناامن Directory Browsing روی وب‌سرور.
  * دکمه اقدام سریع **«دانلود همه فایل‌ها (ZIP)»** جهت فشرده‌سازی درلحظه تمام پیوست‌های پرونده به صورت بسته یکپارچه `Attachments_{trackingCode}.zip`.
* **خروجی تجمیعی هوشمند در گزارش‌های اکسل/CSV:**
  * در فرم‌های دارای فیلد بارگذاری فایل، به جای تولید ستون‌های پراکنده به ازای هر فیلد، دو ستون ثابت و استاندارد در انتهای جدول خروجی درج می‌گردد:
    1. **`تعداد پیوست‌ها`:** تعداد کل فایل‌های ضمیمه‌شده به صورت عدد خالص جهت فیلتر و آمارگیری در اکسل.
    2. **`فایل‌های پیوست`:** درج خودکار فرمول استاندارد اکسل `=HYPERLINK("<origin>/attachments/{trackingCode}", "مشاهده و دانلود پیوست‌ها")` برای دسترسی فوری و تک‌کلیک به پوشه فایل‌های همان پرونده، و درج سلول خالی در صورت عدم وجود پیوست.
* **جدول رسمی پیوست‌های پرونده و بارکد اختصاصی QR در خروجی PDF:**
  * **جدول رسمی ضمایم سند با استایل چاپی شکیل:** فهرست‌بندی خودکار تمامی فایل‌های پیوست با ستون‌های ردیف، نام واقعی فایل (با استخراج هوشمندانه از ساختار پرونده‌های قدیمی)، بج روشن و استاندارد اداری نوع/پسوند فایل (`bg-slate-100 text-slate-800 border font-mono` به جای کادرهای تیره) و دکمه مستقیم دریافت فایل.
  * **دانلود امن و احراز هویت‌شده از پیش‌نمایش چاپ:** اتصال دکمه «دریافت فایل» در پیش‌نمایش به مکانیزم دانلود احراز هویت‌شده با توکن معتبر JWT (فراخوانی برخط و تبدیل به Blob در مرورگر)، همراه با هدایت لینک نهایی در فایل PDF ذخیره‌شده به صفحه پوشه پیوست‌ها (`/attachments/{trackingCode}`).
  * **کد QR اختصاصی «دریافت پیوست‌های پرونده»:** درج بارکد مجزا متصل به صفحه پیوست‌های همان پرونده در کنار جدول، جهت اسکن مستقیم با دوربین گوشی هوشمند از روی برگه چاپ‌شده کاغذی.
  * **سوئیچ اختیاری نمایش تصاویر پیوست:** آپشن قابل تنظیم در طراح قالب و نوار ابزار پیش‌نمایش چاپ PDF جهت چاپ تصاویر پیوست (`JPG`, `PNG`, `WEBP`) در انتهای برگه با کادر شکیل و بدون بریدگی بین صفحات (`break-inside-avoid`)، یا محدودسازی به فهرست‌بندی در جدول پیوست‌ها.

### ۳.۱۵. دید سراسری مدیر، اشتراک‌گذاری فرم و انتقال مالکیت (Form Sharing & Ownership)
* **دید و نظارت سراسری مدیر سیستم (`Admin Global Visibility`):**
  * کاربر دارای نقش `Admin` به کلیه فرم‌های تعریف‌شده در سطح سازمان توسط تمامی کاربران ارشد دسترسی جامع دارد؛ شامل مشاهده، ایجاد نگارش بازنگری جدید، ویرایش شروط و گردش‌کار، استخراج گزارش‌ها و تحلیل در استودیوی هوش مصنوعی و حذف نرم فرم‌ها.
* **اشتراک‌گذاری هدفمند فرم میان کاربران ارشد (`SuperUser Collaboration`):**
  * امکان اشتراک‌گذاری هر فرم توسط طراح اصلی یا مدیر سیستم با سایر کاربران ارشد سازمان با کنترل تفکیک‌شده دو سطح مجوز:
    1. **ویرایش و ایجاد نگارش جدید (`CanEditDesign`):** به کاربر ارشد اجازه می‌دهد نسخه جدیدی از فرم را ایجاد و شروط یا فیلدها را اصلاح کند.
    2. **گزارش‌گیری و تحلیل داده‌ها (`CanViewReports`):** فرم را در کاتالوگ گزارش‌ها و استودیوی پرس‌وجوی هوش مصنوعی کاربر مجاز نمایش می‌دهد.
  * حفظ اکید حقوق مالکیت: دکمه‌های «حذف فرم» و «اشتراک‌گذاری مجدد» منحصراً در انحصار طراح اولیه فرم و مدیر کلان سیستم باقی می‌ماند.
* **انتقال قطعی مالکیت فرم (`Transfer Ownership`):**
  * قابلیت ویژه مدیر سیستم (`Admin`) برای واگذاری مالکیت کامل یک فرم در تمامی نگارش‌ها و بازنگری‌های تاریخی آن به کاربر ارشد دیگر، همراه با اصلاح خودکار حقوق دسترسی و سوابق فرم.

### ۳.۱۶. تعیین تکلیف کارتابل و فرم‌ها هنگام غیرفعال‌سازی کاربر (User Offboarding)
* **بررسی هوشمند پیش از غیرفعال‌سازی (`Offboarding Summary Check`):**
  * در پنل مدیریت کاربران، با کلیک روی گزینه غیرفعال‌سازی هر حساب کاربری، سامانه ابتدا میزان وظایف باز کارتابل سازمانی (`PendingTasksCount`) و تعداد فرم‌های تحت مالکیت وی (`OwnedFormsCount`) را استعلام می‌نماید.
* **تعیین تکلیف اجباری در قالب یک پنجره تعاملی:**
  * در صورت وجود وظایف باز یا فرم‌های سازمانی، پنجره ویژه «تعیین تکلیف کارتابل و فرم‌ها پیش از غیرفعال‌سازی» گشوده شده و با نمایش فهرست دقیق عناوین فرم‌ها و تعداد کارتابل‌ها، مدیر را ملزم به تعیین جانشینان می‌نماید:
    * انتخاب کاربر جایگزین جهت تحویل خودکار وظایف باز کارتابل (همراه با ثبت تاریخچه شفاف در `WorkflowHistories`).
    * انتخاب کاربر ارشد یا مدیر جایگزین جهت انتقال مالکیت فرم‌های سازمانی.
* **اجرای تراکنشی یکپارچه (Single Atomic Transaction):**
  * انتقال کامل وظایف، اصلاح مالکیت فرم‌ها و غیرفعال‌سازی نهایی حساب کاربری در یک تراکنش دیتابیسی واحد اعمال می‌گردد تا از هرگونه توقف یا بلاتکلیفی در فرآیندهای کسب‌وکار جلوگیری شود.

### ۳.۱۷. اسکنر بارکد و QR موبایل (Mobile Barcode & QR Scanner)
* **دسترسی سریع در نمای موبایل (`md:hidden`):**
  * در نوار بالای پنل کاربری و پنجره تکمیل فرم، یک آیکن اختصاصی اسکنر (`ScanLine`) دقیقاً در کنار دکمه تغییر تم قرار گرفته است که صرفاً روی گوشی‌های هوشمند و تبلت‌های کوچک نمایش داده می‌شود و در دسکتاپ مخفی می‌ماند تا فضای دسکتاپ خلوت باقی بماند.
* **رمزگشای هیبریدی ۱۰۰٪ آفلاین (بدون نیاز به اینترنت):**
  * مودال درون‌برنامه‌ای اسکنر (`MobileBarcodeScannerModal.jsx`) در صورت پشتیبانی مرورگر از استاندارد بومی `BarcodeDetector` برای اسکن زنده دوربین پشت (`facingMode: "environment"`) استفاده می‌کند و در کنار آن از مفسر آفلاین بومی (`offlineBarcodeDecoder.js` برای QR Code و بارکدهای تک‌بعدی Code 128 / Code 39) درون باندل پروژه بهره می‌برد.
* **پشتیبانی کامل در شبکه‌های HTTP پیش از فعال‌سازی SSL:**
  * در استقرارهای موقت روی بستر `http://` که مرورگرهای موبایل اجازه استریم زنده دوربین (`getUserMedia`) را مسدود می‌کنند، سامانه به جای خطای مبهم، پیام راهنمای شفاف فارسی نمایش داده و هم‌زمان دکمه **«عکس‌برداری از بارکد با دوربین گوشی»** (`<input type="file" accept="image/*" capture="environment">`) را برای رمزگشایی دقیق از تصویر ثبت‌شده فعال می‌نماید.
* **اقدامات هوشمند پس از اسکن:**
  * کپی خودکار مقدار اسکن‌شده در کلیپ‌بورد (Clipboard).
  * تشخیص هوشمند کدهای رهگیری (`TRK-...`) و لینک‌های پرونده نوافلو و نمایش دکمه مستقیم **«مشاهده و باز کردن پرونده»** جهت پرش آنی به پرونده مربوطه در کارتابل/پیگیری.
  * دکمه‌های سریع **«درج در فیلد فعال فرم»** (تزریق خودکار در آخرین فیلد متنی/عددی، سلول جدول اقلام یا جستجوی Lookup فعال) و **«جستجو در کارتابل»**.

### ۳.۱۸. نصب‌شوندگی PWA موبایل با استراتژی Network-First
* **مانیفست فارسی و حالت تمام‌صفحه (`Standalone`):**
  * افزودن فایل `manifest.json` با نام فارسی `نوافلو - سامانه هوشمند فرآیندها`، جهت راست‌چین (`rtl`)، حالت اجرای مستقل (`standalone`) مشابه اپلیکیشن‌های بومی، متاتگ‌های استاندارد موبایل (`theme-color`، `apple-mobile-web-app-capable`) و آیکن‌های استاندارد `192x192`، `512x512` و `maskable`.
* **سرویس‌ورکر Network-First (`sw.js`) ضدکش قدیمی:**
  * فایل `sw.js` با استراتژی **Network-First** ثبت شده است تا قابلیت **Add to Home Screen** (نصب روی صفحه اصلی iOS و Android) فعال شود و در عین حال باندل‌های به‌روز JS/CSS یا درخواست‌های `/api/` و `/uploads/` پس از آپدیت سرور هرگز در کش قدیمی گرفتار نشوند.

### ۳.۱۹. تنظیمات پویای پالیسی گذرواژه و قفل شدن حساب‌های محلی
* **مدیریت متمرکز در تب تنظیمات (`#settings`):**
  * مدیر سیستم می‌تواند در کارت جدید **«سیاست گذرواژه و امنیت حساب‌های محلی (Password & Lockout Policy)»** قواعد زیر را به‌صورت پویا تنظیم و در دیتابیس (`SystemSettings`) ذخیره کند (با تفکیک شفاف مبنی بر اینکه این قواعد مختص حساب‌های محلی است و شامل کاربران Active Directory نمی‌شود):
    * فعال/غیرفعال‌سازی الزامات پیچیدگی گذرواژه (`EnablePasswordPolicy`) و حداقل طول رمز عبور قابل تنظیم از `6` تا `32` کاراکتر (`MinPasswordLength`).
    * چک‌باکس‌های الزام حروف بزرگ انگلیسی (`A-Z`)، حروف کوچک (`a-z`)، اعداد (`0-9`) و کاراکترهای ویژه (`!@#$%^&*`).
    * کنترل قفل خودکار حساب‌های محلی (`EnableAccountLockout`) شامل سقف تلاش‌های ناموفق مجاز (`MaxFailedLoginAttempts`) و مدت‌زمان قفل ماندن حساب به دقیقه (`LockoutDurationMinutes`).
* **اعمال در سمت سرور و پنل مدیریت کاربران (`#users-management`):**
  * هنگام ایجاد کاربر محلی جدید، بازنشانی رمز عبور و ورود در `/api/auth/login`، سیاست‌های فعلی به صورت زنده بررسی شده و پیام‌های خطای دقیق فارسی (شامل تعداد تلاش‌های باقی‌مانده یا زمان باز شدن قفل) بازگردانده می‌شود؛ همچنین مدیر می‌تواند با دکمه **«باز کردن قفل (Unlock)»** در `#users-management` حساب‌های قفل‌شده را با یک کلیک آزاد نماید.

## ۴. یکپارچه‌سازی و مستندات REST API

سامانه نوافلو (NovaFlow) بر مبنای معماری مدرن **API-First** توسعه یافته است. تمامی قابلیت‌های سامانه—شامل احراز هویت، کاتالوگ فرم‌ها، ثبت پرونده با جداول اقلام پویا (`repeater_grid`)، پیگیری و کارتابل تاییدات (`Inbox` / `Outbox` / `CC`)، مدیریت بانک داده‌های مرجع (`Master Data Hub`) و گزارش‌گیری—دارای وب‌سرویس‌های استاندارد RESTful با پروتکل امن HTTPS و بدنه JSON می‌باشند.

این معماری امکان اتصال بدون واسطه و پایدار سامانه‌های پیرامونی سازمان (از جمله سامانه‌های یکپارچه ERP، نرم‌افزارهای انبار و تدارکات، حسابداری، پورتال پرسنلی و بات‌های اتوماسیون اداری) را بدون نیاز به باز کردن رابط کاربری تحت وب فراهم می‌سازد.

### مستندات فنی و راهنماهای یکپارچه‌سازی:
* 🌐 **[مستند فنی وب‌سرویس‌ها (API.md)](API.md):** مرجع کامل توسعه‌دهندگان شامل ماتریس Endpointها، پارامترهای ورودی/خروجی، نمونه کدهای آماده به زبان PowerShell (`Invoke-RestMethod`) و cURL، نمونه ساختارهای کامل JSON برای سناریوهای کلیدی و جدول کدهای وضعیت HTTP.
* 📄 **[راهنمای جامع وب‌سرویس‌ها (NovaFlow_API_Reference_Guide.docx)](NovaFlow_API_Reference_Guide.docx):** فایل مرجع مستقل سازمانی و قابل چاپ در قالب Word با جداول تفکیک‌شده، استانداردهای امنیتی، مدیریت خطاها و دیاگرام‌های تبادل داده.

#### نمونه فراخوانی سریع با PowerShell:
```powershell
# ورود و دریافت توکن JWT
$auth = Invoke-RestMethod -Uri "https://bpms.example-org.ir/api/auth/login" -Method Post -Body (@{ username = "a.mohammadi"; password = "Password@12345" } | ConvertTo-Json) -ContentType "application/json; charset=utf-8"
$headers = @{ "Authorization" = "Bearer $($auth.token)"; "Accept" = "application/json" }

# دریافت لیست کارتابل ورودی
$inbox = Invoke-RestMethod -Uri "https://bpms.example-org.ir/api/workflow/inbox" -Method Get -Headers $headers
```

## ۵. معماری و ساختار پایگاه‌داده

سامانه نوافلو از یک مدل ترکیبی رابطه‌ای (Relational) و اسکیمای ساختاریافته (JSON) با بهره‌گیری از قابلیت‌های Native JSON در SQL Server و کالکشن استاندارد فارسی (`Persian_100_CI_AI`) استفاده می‌نماید:

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                           جداول هسته سامانه (Core Schema)                       │
├──────────────────────────┬──────────────────────────────────────────────────────┤
│ Users, Roles, UserRoles  │ مدیریت کاربران سازمانی، نگاشت نقش‌ها و احراز هویت     │
│ Forms, FormVersions      │ تعاریف فرم‌ها، فیلدها، سکشن‌ها و نسخه‌بندی ساختار فرم  │
│ Workflows, Steps, Rules  │ ماتریس مراحل تاییدات، شروط BRMS و قوانین ارجاع      │
│ Requests, RequestSteps   │ پرونده‌های در گردش، تاریخچه اقدامات و هامش‌ها        │
│ Attachments              │ نگهداری فراداده و مسیر ذخیره‌سازی پیوست‌های مجاز     │
├──────────────────────────┴──────────────────────────────────────────────────────┤
│                   جداول ماژول بانک داده‌های مرجع (Master Data Hub)              │
├──────────────────────────┬──────────────────────────────────────────────────────┤
│ MasterDataConnections    │ اتصالات سرورهای SQL Server خارجی با رمزنگاری AES-256 │
│ MasterDataTables         │ تعاریف جداول مرجع، نگاشت ستون‌ها، فیلترها و زمان‌بندی  │
│ MasterDataRecords        │ آینه و کش محلی رکوردهای مرجع با ایندکس مرکب بهینه    │
└──────────────────────────┴──────────────────────────────────────────────────────┘
```

### مشخصات و ساختار جداول بانک داده‌های مرجع:
1. **جدول اتصالات خارجی (`MasterDataConnections`):**
   * `Id`: شناسه یکتای اتصال (Primary Key).
   * `Title`: عنوان توصیفی اتصال (مثلاً «اتصال به پایگاه داده ERP دفتر مرکزی»).
   * `ServerAddress`: نشانی شبکه یا IP سرور SQL Server مقصد.
   * `DatabaseName`: نام پایگاه داده هدف در سرور مقصد.
   * `AuthType`: مدل احراز هویت شامل `Sql` (نام کاربری و رمز) یا `Windows` (احراز هویت ویندوزی).
   * `Username`: نام کاربری دیتابیس یا حساب سرویس اکانت ویندوز دامنه.
   * `EncryptedPassword`: گذرواژه ذخیره‌سازی‌شده با رمزنگاری متقارن قدرتمند AES-256.
   * `Domain`: نام دامنه شبکه سازمانی برای سرویس اکانت‌های دامین در حالت Windows Auth.
   * `IntegratedSecurity`: فلگ استفاده مستقیم از هویت سرویس محلی سرور وب (IIS AppPool Identity).
   * `CreatedAt` / `UpdatedAt`: زمان ثبت و آخرین به‌روزرسانی تنظیمات اتصال.

2. **جدول تعاریف جداول مرجع (`MasterDataTables`):**
   * `Id`: شناسه یکتای جدول مرجع.
   * `ConnectionId`: کلید خارجی ارجاع به جدول `MasterDataConnections` (در منابع SqlQuery).
   * `Code`: کد لاتین یکتای جدول جهت فراخوانی در فرم‌ساز (مانند `CUSTOMERS`, `PRODUCTS`, `COST_CENTERS`).
   * `Title`: عنوان فارسی نمایشی جدول مرجع در سامانه.
   * `SourceType`: منبع تامین داده شامل `Manual` (ورود دستی)، `Excel` (ایمپورت فایل) یا `SqlQuery` (اتصال SQL).
   * `SqlQuery`: متن دستور فقط-خواندنی SQL جهت استخراج داده‌ها از سرور مبدأ.
   * `UniqueKeyColumn`: نام ستون کلید اصلی و تمایزبخش رکوردها جهت اجرای الگوریتم Upsert.
   * `ColumnsJson`: ساختار و اسکیمای ستون‌ها (نام لاتین، عنوان فارسی، نوع داده) در قالب JSON.
   * `FilterRulesJson`: آرایه‌ای از قوانین فیلترینگ پیش از استخراج با عملگرهای استاندارد.
   * `ExcludedKeysJson`: آرایه‌ای از شناسه‌های کلید استثناشده دستی توسط کاربر.
   * `ScheduleConfigJson`: ساختار کامل تنظیمات زمان‌بندی پیشرفته PBI-Style (الگو، ساعت، فواصل، روزهای کاری، ماه‌های شمسی).
   * `SyncScheduleType` / `SyncScheduleValue`: مقادیر زمان‌بندی جهت کوئری‌های سریع سرویس پس‌زمینه.
   * `LastSyncAt` / `LastSyncStatus` / `LastSyncError`: تاریخچه، نتیجه و خطای آخرین همگام‌سازی.
   * `RecordCount`: تعداد کل رکوردهای فعال موجود در کش محلی.
   * `VersionHash`: هش محتوایی داده‌ها جهت اعتبارسنجی کش حافظه کلاینت.
   * `IsActive`: وضعیت فعال یا بایگانی بودن جدول مرجع.

3. **جدول داده‌ها و کش محلی رکوردهای مرجع (`MasterDataRecords`):**
   * `Id`: شناسه رکورد.
   * `TableId`: کلید خارجی ارجاع به جدول `MasterDataTables`.
   * `UniqueKeyValue`: مقدار متنی ستون کلید اصلی برای جستجو و تطبیق سریع در Upsert.
   * `RowDataJson`: کل داده‌های یک سطر در قالب ساختاریافته JSON.
   * `IsActive`: نشانگر وضعیت فعال بودن رکورد (با پشتیبانی از Soft-Deactivation).
   * `CreatedAt` / `UpdatedAt`: زمان درج اولیه و آخرین همگام‌سازی سطر.
   * **ایندکس مرکب با کارایی بالا:** `IX_MasterDataRecords_Lookup ON (TableId, IsActive, UniqueKeyValue)` جهت استعلام و فیلترینگ با سرعت میلی‌ثانیه‌ای در فرم‌های سازمانی با صدها هزار رکورد.

## ۷. شروع به کار و استقرار سریع

 برای راه‌اندازی سریع سامانه در سرور عملیاتی:
1. مطمئن شوید پیش‌نیازهای **IIS**، ماژول **IIS URL Rewrite 2.1** و بسته **.NET 8 Hosting Bundle** نصب شده باشند.
2. اسکریپت استقرار خودکار را با مجوز مدیر اجرا فرمایید (برای راه‌اندازی HTTPS و Wildcard SSL هنگام اجرا کلید `Y` را وارد کرده و گواهی مخزن `Cert:\LocalMachine\My` را انتخاب نمایید):
   ```powershell
   Set-ExecutionPolicy Bypass -Scope Process -Force
   .\Deploy-BPMS.ps1
   ```
   * **مدیریت گذرواژه مدیر محلی (`local_admin`) هنگام نصب و ارتقا:** اسکریپت `Deploy-BPMS.ps1` در مرحله پیکربندی گزینه حفظ رمز فعلی (پیش‌فرض برای حفظ رمز در ارتقا یا اعمال رمز اولیه `Admin@123456` در نصب نو) یا بازنشانی رمز عبور جدید را ارائه می‌دهد. هسته سرور (`BPMS.Server.dll`) همچنین در حالت CLI از فلگ `--reset-admin-password` همراه با متغیر محیطی `BPMS_RESET_ADMIN_PASSWORD` پشتیبانی می‌کند تا رمز عبور `local_admin` را با `PBKDF2` بازنشانی کرده و شمارنده خطای ورود و وضعیت قفل حساب آن را آزاد نماید.
3. برای انتشار پشت Reverse Proxy / WAF / CDN، تنظیمات بخش `HttpsSettings` (`EnableHttpsRedirect`, `EnableHsts`, `TrustForwardedHeaders`) در فایل `appsettings.json` تعبیه شده است.
4. **حذف ایمن سامانه (`Uninstall-BPMS.ps1`):** پیش از حذف سایت IIS و فایل‌های سامانه، اسکریپت `Uninstall-BPMS.ps1` علاوه بر تاییدیه اولیه، به‌صورت اجباری وجود نسخه پشتیبان کامل (`.bpmsbackup`) دریافت‌شده از تب **«پشتیبان‌گیری و بازیابی»** را استعلام کرده و در صورت تایید نکردن، عملیات را متوقف می‌سازد؛ همچنین در گام دوم نسخه پشتیبان سریع از پوشه `uploads` و فایل `appsettings.json` روی دسکتاپ ذخیره می‌شود.
5. جهت مطالعه راهنمای گام‌به‌گام نصب آفلاین، راهنمای فعال‌سازی HTTPS/Wildcard SSL، تنظیمات پایگاه‌داده و حل خطاهای احتمالی، به مستند [راهنمای جامع نصب و استقرار (INSTALL.md)](INSTALL.md) مراجعه نمایید.
